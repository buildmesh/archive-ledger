# Guarded 400k inventory import and rebuild

Tracked by **al-j5k**, following the [quiet-host 200k run](2026-09-25-rebuild-io.md#quiet-host-completion-with-more-scope-headroom).
The user authorized 400k and use of the root partition. The inventory-only
import completed uninterrupted, and a full rebuild subsequently completed in
**276.87 seconds**. Exact derived-table comparisons and routine fsck passed.

## Workload and controls

The fixture contained 400,000 distinct deterministic annex keys and dangling
symlinks, created in 40 guarded batches of 10,000. Git's committed tree and
index both contained exactly 400,000 symlinks. Nominal 1,024-byte content sizes
are metadata; no media contents were generated or read.

The same diagnostic release executable as the latest 200k run was reused:
`/home/ubuntu/tmp/archive-ledger-al-j5k-replay-xggzy6_z/target/release/archive`,
SHA-256 `702a3df975b37abfc23a8424c577f4b09ac3b94fdef4d723a0de2ede191fa1c3`.
There was no compilation or production code change. Rebuild retained its
64-record transaction groups, 64 MiB SQLite cache, prepared statements,
deferred reporting indexes, and FULL/DELETE durability.

Staging used root-backed ext4 on `/dev/nvme0n1p1`, initially with about 16.8 GiB
free. Earlier fixtures used the separate `/home/ubuntu` volume. Hermes remained
stopped as previously authorized; other sessions and services were untouched.

All phases used one-core affinity, nice 10, idle I/O priority, and these guards:

- 2,560 MiB available-RAM preflight and quiet memory PSI.
- 2,048 MiB hard limit, zero scope swap, 1,920 MiB early stop, and 512 MiB host reserve.
- Stop after five seconds of memory PSI some avg10 above 5% or full above 2%.
- 8 GiB free-root-space preflight and 4 GiB free-space stop.
- A 1,536 MiB soft limit initially; 1,792 MiB for the successful final rebuild
  and subsequent validation, after the bounded adjustment described below.

Import had a 5,400-second scope timeout; other individual phases had 1,200
seconds. Launchers and guard assertions were smoke-tested. Actual command
timings exclude fixture creation and external comparison/health checks.

No resume, manual publication recovery, or separate apply command was needed.

## Rebuild attempts and mitigation

The first attempt stopped on memory PSI at 391.32 scope seconds during
`integrity_check`, after replay, index construction, and optimization. Its
scope peaked at 1,461.05 MiB, below the soft limit, with no limit events and
at least 2,727 MiB available host RAM. It did not complete a rebuild.

The host retained roughly 1.3 GiB of reclaimable filesystem metadata. Removing
only the verified disposable source repository reduced that to about 125 MiB.
The successful importer had already removed its spool. A cleanup helper first
exited on that missing-spool assertion; the corrected final cleanup verified
the preserved databases and removed the schema-zero partial rebuild. No
canonical history or reference database was removed.

A retry with unchanged limits stopped on PSI at 284.12 scope seconds, again
during integrity checking. This time it reached 1,536.07 MiB with 2,581
soft-limit events, despite at least 2,648.57 MiB available host RAM. Index
construction was much faster after source cleanup, but validation still faced
scope reclaim. This second incomplete output also retained schema version zero
and was removed.

The next attempt raised only the soft limit to 1,792 MiB. The hard limit,
early stop, no-swap rule, host reserve, and pressure thresholds stayed intact.
It completed without soft-limit events or a pressure stop. The sequence changes
cache state as well as available scope headroom; it does not isolate a causal
speedup from any one change or establish a minimum RAM requirement.

## Validation and retained evidence

All 31 event-derived tables and the complete schema matched the independent
incremental reference, using equal counts and bidirectional SQL `EXCEPT`.
The established exclusions are local `jobs`/`job_items` and four `archive_meta`
keys: `projection_generation`, `policy_input_generation`,
`last_verified_checkpoint_id`, and `last_verified_checkpoint_frontier_hash`.
All five principal inventory tables contain exactly 400,000 rows. The database
completion marker is version six, with no remaining rebuild or SQLite sidecars.

Routine fsck completed in 97.68 scope seconds, reporting healthy and current;
every requested check passed. `fsck --full` was not run: the independent exact
comparison above supplies the rebuild-equivalence check. No separate full
integrity scan of the incremental reference is claimed. Canonical Git remained
clean at `a33410781d0cfdda2cb7a9e708b6cbd68ae77e14`; all comparison input
identities were unchanged through fsck.

All 86 guard reports were audited, including the two pressure-stopped rebuilds
and the cleanup-helper assertion failure. Every report had zero hard-limit,
OOM, and OOM-kill events, zero scope swap, and unchanged global OOM-kill counts.
Minimum sampled available host RAM was 2,580.64 MiB and minimum free disk was
8,982.39 MiB. No benchmark scope remained active at the end of this run.
Hermes was stopped during these measurements.
Production tests were not rerun because production code did not change;
measured reconstruction, exact comparison, fsck, and report diff checks are
this experiment's validation.
